上下文望远镜：一次 AI 对话，LLM 到底看见了什么

拖动下方的滑块，"望远镜"会从左往右扫过一整次对话。窗口里是 LLM 每一 call 实际看到的信息；窗口外变灰的是"发生过、但已不在窗口里"的历史；带红纹的是被上下文裁剪丢掉的。来回滑动，看清 Agent 每一步在干什么、上下文为什么被裁。

系统提示词 工具定义（tools 字段） 用户消息 助手消息 / tool_calls 工具结果（role=tool）
对话轨道 · 从左到右 = 时间顺序

滑动观测

1当前窗口里有什么（按对话构成分类）

2裁剪事件（窗口外发生了什么）

三分钟看懂这套设计：
  1. 一次对话 = 多次 LLM call。Agent 每转一圈就带着"当前窗口"问一次模型；模型要么回 tool_calls（继续转），要么回最终答案（收场）[1]。
  2. 窗口是固定预算。系统提示词 + 工具定义每 call 必带（稳定、优先）；消息历史随对话增长，是最先膨胀的部分[2]。
  3. Context rot：token 越多，召回越差。所以超预算就要裁——裁剪的目的不是省 token，是把注意力留给此刻最该看的东西[2]。
  4. 裁剪有规矩：从最老的消息丢、保底留最近几条、tool_calls 与工具结果必须同组丢（孤儿 tool 消息会被 API 拒绝）。教学版用"丢弃"，生产产品（Codex / Claude Code）普遍升级为"先摘要再丢"，官方实测同一模型分数差 3 倍[3][4]。
  5. 生产三件套：对话膨胀→压缩（compaction）；工具膨胀→清结果留记录（tool-result clearing）；知识要跨会话→外置记忆（memory tool）[5]。
